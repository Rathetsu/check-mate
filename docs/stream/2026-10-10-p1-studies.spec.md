# Spec: Studies

Date: 2026-10-10
Status: Approved (design; no code yet)
Phase: 1 · Milestone M1.4

## Goal

Private, persistent studies in the style of Lichess Studies. A study holds
chapters. Each chapter is an analysis tree with variations, comments,
annotations and arrows. It is created from scratch, a FEN, a PGN, a puzzle, an
explorer position (P2) or a library game (P3).

Decisions: 2026-10-10-13-study-chapters-stored-as-pgn ·
2026-10-10-11-raw-player-data-append-only-aggregates-derived.

## Scope

In: CRUD for studies and chapters, chapter sources, editing via the analysis
board, autosave, reorder, export, limits.
Out: public sharing, collaborative or live editing, study likes, comments
from others, interactive "guess the move" chapters (COULD later), embedding.

## User flows

1. `/studies` → "New study" → name → empty study with chapter 1 (start
   position).
2. "Add chapter" → choose a source:
   - Empty
   - From FEN (opens the editor)
   - From PGN (paste or file; multi-game PGN → one chapter per game, up to
     the cap)
   - From puzzle (puzzle history)
   - From explorer position (P2)
   - From my games (P3)
3. Edit the chapter using the analysis board UI. Saves happen automatically;
   a status indicator shows "Saved".
4. Rename, reorder (drag) or delete chapters; rename or delete the study.
5. Export the chapter PGN, or the whole study as multi-game PGN.

## Requirements

- **P1-ST-01 MUST** Create, rename, describe and delete studies. Deleting
  needs confirmation and cascades to chapters.
- **P1-ST-02 MUST** Add chapters from every source listed above. Sources
  marked (P2)/(P3) arrive in those phases and must use the same "create
  chapter from PGN/FEN" service call.
- **P1-ST-03 MUST** Chapter fields: name, orientation, PGN (the whole tree),
  order, version.
- **P1-ST-04 MUST** Editing reuses the analysis board (engine, annotations,
  arrows, tree operations) with `TreeCursor` loaded from the chapter PGN.
- **P1-ST-05 MUST** Autosave:
  - Debounced 2 s after the last change, and on page hide.
  - Sends `PUT` with `version`. The server rejects a stale version with 409,
    and the UI offers "Reload latest" or "Overwrite".
  - Saves are never silently lost: unsaved changes block navigation with a
    prompt.
- **P1-ST-06 MUST** Server-side validation: chapter PGN is parsed by
  `packages/chess` before it is stored. Invalid PGN is rejected with the
  PGN/FEN error envelope.
- **P1-ST-07 MUST** Reorder chapters (drag on desktop, move up/down on
  mobile). Order is stored as an integer.
- **P1-ST-08 MUST** Export:
  - Chapter → `.pgn` with `[Event "<study>: <chapter>"]`, `[StudyName]` and
    `[ChapterName]` headers.
  - Study → one multi-game `.pgn`.
- **P1-ST-09 MUST** Limits: 64 chapters per study (Lichess parity), 500 KB
  PGN per chapter, 200 studies per user. Hitting a limit gives an error, not
  a silent truncation.
- **P1-ST-10 MUST** Study list shows name, chapter count, updated time, and a
  thumbnail board of chapter 1's current position. Searchable by name.
- **P1-ST-11 MUST** All study data is private to its owner (CORE-50..52).
- **P1-ST-12 SHOULD** "Duplicate study" and "Move chapter to another study".
- **P1-ST-13 SHOULD** Last opened chapter and node are remembered per study.

## Data model

```
studies (id uuid PK, user_id FK CASCADE, name text, description text,
  created_at, updated_at)
study_chapters (id uuid PK, study_id FK CASCADE, user_id FK CASCADE,  -- denormalized for scoping
  ord int, name text, orientation text,
  pgn text,                         -- single source of truth (ADR 13)
  initial_fen text,                 -- derived from pgn on save, for thumbnails
  source_type text, source_id text, -- 'blank'|'fen'|'pgn'|'puzzle'|'explorer'|'game'
  version int NOT NULL DEFAULT 1,
  created_at, updated_at)
UNIQUE (study_id, ord) DEFERRABLE
```

## API surface

- `GET/POST /api/v1/studies`; `GET/PATCH/DELETE /api/v1/studies/:id`
- `POST /api/v1/studies/:id/chapters` with body `{source_type, name, pgn? | fen? | puzzle_id? | game_id?}`. A multi-game PGN returns the created chapter ids.
- `GET/PUT/PATCH/DELETE /api/v1/studies/:id/chapters/:chapterId`. `PUT` carries `{pgn, version}` and returns the new version or 409.
- `POST /api/v1/studies/:id/reorder` with `{chapterIds[]}`
- `GET /api/v1/studies/:id/export.pgn`; `GET .../chapters/:chapterId/export.pgn`

## Chess-authority notes

The server validates chapter content through the rules layer. Study text
(comments) is user-authored and never treated as chess truth.

## Phase 4 hooks

`/api/v1/studies/*` lets the AI service read what openings and positions the
user studies. Chapter `source_type`/`source_id` link studies back to games
and puzzles.

## Acceptance criteria

- Playwright:
  - create a study → add 3 chapters (blank, FEN, 2-game PGN, which makes 4
    chapters) → annotate → reload → all annotations persist
  - export the study → re-import as a new study → identical chapters
- Two tabs edit the same chapter: the second save gets a 409 with a working
  "Reload latest".
- Posting a chapter with an illegal move returns 400 `ILLEGAL_MOVE` with the
  ply.
- The 65th chapter is rejected with a clear message.
- Cross-user access to a study returns 404.

## Open questions
