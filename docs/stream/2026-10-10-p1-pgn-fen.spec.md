# Spec: PGN and FEN import/export

Date: 2026-10-10
Status: Approved (design; no code yet)
Phase: 1 · Milestone M1.1 (library), used by every later feature

## Goal

One correct, lossless PGN/FEN layer used everywhere: analysis, editor,
studies, puzzles, the P2 explorer, and P3 imports. It parses through the
rules layer, preserves as much PGN as possible, and gives errors a human can
act on.

Decisions: 2026-10-10-07-chessops-is-the-rules-layer ·
2026-10-10-02-chess-software-is-sole-source-of-chess-truth.

## Scope

In: PGN parse/write (single and multi-game, streaming), FEN parse/validate/
write, error reporting, import/export UI primitives (paste, file, copy,
download).
Out: Chess.com/Lichess API import (P3), bulk import jobs (P3 reuses this
library inside the worker).

## Requirements

### Parsing

- **P1-PG-01 MUST** Parse PGN via chessops `parsePgn`/`startingPosition`,
  covering:
  - Seven Tag Roster plus **all other tags**, kept verbatim and in order
    (including unknown tags such as `[Site]`, `[Link]`, `[ECOUrl]`,
    `[TimeControl]`)
  - mainline and nested variations (RAV)
  - comments before and after moves, including the game-level comment
  - NAGs, both numeric `$n` and glyph forms (`!`, `?`, `!!`, `??`, `!?`,
    `?!`)
  - comment commands: `[%cal]`, `[%csl]` (to shapes), `[%clk]` (to clock),
    `[%eval]` (to `importedEval`)
  - custom `[FEN]` / `[SetUp]` starting positions
- **P1-PG-02 MUST** Multi-game files:
  - Streaming parse that returns a game list with headers, index and
    parse status, without materializing every tree at once.
  - Files over 1 MB parse in a Web Worker in the browser (or the server
    worker for P3 jobs), so the UI thread is never blocked.
- **P1-PG-03 MUST** Every SAN move is validated by applying it to the current
  position. The first illegal or ambiguous move stops that game with an error.
  Other games in the file are unaffected.
- **P1-PG-04 MUST** Error objects carry `{gameIndex, line, column, ply?,
  san?, code, message}`. The message names the move and position ("Move 23.
  Nxe5 is illegal in this position"). Error codes include `PGN_SYNTAX`,
  `ILLEGAL_MOVE`, `AMBIGUOUS_MOVE`, `BAD_FEN_TAG`, `UNSUPPORTED_VARIANT`, and
  `TOO_LARGE`.
- **P1-PG-05 MUST** A `[Variant]` other than Standard/From Position (or a
  Chess960 FEN castling setup) gives `UNSUPPORTED_VARIANT` in the analysis
  board and studies (CORE-70). The P3 importer stores such games raw instead.
- **P1-PG-06 MUST** Tolerate common real-world quirks:
  - missing result
  - `0-0` written with zeros
  - `e8=Q` and `e8Q`
  - BOM and CRLF
  - Chess.com's `{[%clk ...]}` comments
  - trailing whitespace
  - games separated by blank lines only

### FEN

- **P1-PG-10 MUST** FEN parse plus `validateSetup` returns either ok, or a
  list of reasons mapped from chessops `IllegalSetup`:
  - empty board
  - opposite side in check
  - pawns on the back rank
  - wrong number of kings
  - variant mismatch
  - bad castling rights for piece placement
  - invalid en passant square
- **P1-PG-11 MUST** Accept 4-, 5- and 6-field FENs, defaulting to `0 1`
  counters. Normalize on output.
- **P1-PG-12 MUST** FEN in URLs (`/analysis/<fen>`) uses `_` for spaces,
  Lichess-style. Invalid URL FENs show a validation error, never a crash.

### Writing / export

- **P1-PG-20 MUST** `makePgn` writes headers, mainline, variations, comments,
  NAGs, and shapes (`[%cal]/[%csl]`). Clocks and imported evals are written
  back when present.
- **P1-PG-21 MUST** Round-trip: parse → write → parse produces an identical
  tree for every fixture in the corpus (structure, comments, NAGs, shapes,
  headers).
- **P1-PG-22 MUST** Export actions:
  - copy PGN
  - download `.pgn` (filename from the headers)
  - copy FEN of the current node
  - copy a shareable link
- **P1-PG-23 SHOULD** Export options: with or without variations, comments
  and clocks (Lichess parity). *(2026-10-11: build in Phase 1.)*

### Limits

- **P1-PG-30 MUST** In-browser paste or upload is capped at 10 MB and 5,000
  games per file (the editor/analysis "pick a game" list). Bigger files are
  routed to the P3 library import, which is worker-based and allows 50 MB.
- **P1-PG-31 MUST** A single game tree is capped at 20,000 nodes, with a
  clear error. This guards against pathological variation trees.

## Provenance rule

- **P1-PG-40 MUST** `[%eval]` values from imported PGN are stored as
  `importedEval {value, depth?, source: 'imported'}`. They are displayed
  labelled "from PGN", never in the engine panel or eval bar as CheckMate
  analysis (2026-10-10-02).

## Fixture corpus (`packages/chess/fixtures/`)

- A Lichess study export with nested variations, shapes and comments, from
  a study we author ourselves (no third-party study content).
- A Lichess game export with `%clk`, `%eval` and opening tags (CC0).
- A Chess.com monthly archive PGN (multi-game, `%clk`, `[ECOUrl]`), from the
  maintainer's own games or written synthetically in the same format. No
  other players' Chess.com data enters the repo
  (2026-10-10-14-self-hosted-opening-explorer-from-licensed-data).
- A Lichess broadcast round (CC BY-SA; attribution kept in the fixture
  README).
- A malformed set: illegal move mid-game, ambiguous SAN, bad FEN tag, a
  Chess960 game, a truncated file, an empty file.

The fixture folder and each file's source and license are listed in the
fixture README and registered in `docs/wiki/open-source-reuse.md`.

## API surface

None on its own. The library is used by the analysis, studies and import
endpoints. Server-side validation reuses the same `packages/chess` code.

## Reuse

| Component | Mode |
|---|---|
| chessops `pgn`, `fen`, `san`, `setup` | reused |
| Error mapping and fixtures | independent |

## Phase 4 hooks

The AI service receives positions and lines as FEN + UCI or PGN produced by
this layer, so it never parses user-supplied text itself.

## Acceptance criteria

- The round-trip test passes on the whole corpus.
- Each malformed fixture yields the expected error code, line and ply.
- A 5 MB, 3,000-game PGN pasted into analysis lists its games in under 3 s on
  a mid-range laptop, with no long tasks over 200 ms on the main thread.
- Exported PGN opens in Lichess's study import with variations, comments and
  arrows intact (manual check, recorded once in the stream).
